          Answer the passkey verification WhatsApp asks for while linking a
          device to an account that has a passkey.


          When it does, the session emits an `auth.passkey` event with `step:
          verify` and the WebAuthn request options in `publicKey`. Sign them
          with `navigator.credentials.get()` on a page served from
          `web.whatsapp.com` (WebAuthn only accepts WhatsApp's own origin for
          its relying party), then send the resulting credential here within the
          event's `expiresAt`. A rejected assertion leaves the verification
          open, so it can be retried.


          WhatsApp may then ask the user to compare a code with the phone: an
          `auth.passkey` event with `step: confirm` and `code`. Answer it with
          the confirm route.


          Requires `manage` capability; session must be unpaired.


          Errors: `validation_error` (400), `not_found` (404), `conflict` (409,
          no verification pending), `unauthorized` (401), `forbidden` (403).
