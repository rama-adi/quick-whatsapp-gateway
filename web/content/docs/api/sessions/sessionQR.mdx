      - content: >-
          Read the session's current pairing QR code. This only reads; it never
          starts pairing (use `:start` or create with `start: true`).


          - `state: ready` with `code` (and `expiresAt`) while a code exists.

          - `state: pending` while the session is pairing but WhatsApp has not
          sent a code yet; poll again or wait for the `auth.qr` event.

          - `409 conflict` when the session is not pairing: already paired, not
          started (`desiredState: stop`), logged out, or its pairing failed. A
          failed pairing carries `details.failureReason` (for example
          `qr_timeout`); start the session again for new codes.

          - `503 gateway_unavailable` when the session's gateway is not
          connected.


          Requires `manage` capability.


          Errors: `not_found` (404), `conflict` (409), `gateway_unavailable`
          (503), `unauthorized` (401), `forbidden` (403).
